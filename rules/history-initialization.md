# 履歴領域の初期化ルール

scope: all-workers
thread-scope: all-threads
status: active

## 目的

`history/`をGit追跡対象外のローカル領域として運用する場合でも、新規運用開始時からタスク退避、復旧、統合候補判定が停止しないよう、履歴領域と`history/index.md`を安全に初期化する。

## 初期化の適用タイミング

- agent-workflowを新しい対象リポジトリへ初めて展開した時
- 初回タスクの`result/current-task.md`を作成する前または作成直後
- タスク退避、復旧、統合候補判定を開始する前に、履歴領域の初期化が未確認である時
- 既存の`history/`を持たない移行先で、初回の履歴台帳を準備する時

初期化済みの移行先で`history/index.md`が欠落、読取不能、形式不一致になった場合は、初期化として上書きせず、履歴操作を停止してOwnerへ報告する。既存スナップショットがある状態でのhisi復旧は、初回初期化とは別の復旧工程として扱う。

## 初期化手順

次の順序で実施する。特定の言語、shell、実行可能プログラム、外部ライブラリは前提にしない。

1. `history/`の存在、`history/index.md`の存在、Git追跡対象外の設定を確認する。
2. `history/`が存在しない場合だけ、空のローカル履歴領域として作成する。
3. `history/index.md`が存在しない場合、`history/`に通常の履歴スナップショット（`history/<task-id>/`）や不明な資料がないことを確認する。今回の特殊な保全領域である`history/task-legacy-history-backup/`は、この初期化判定の対象外とし、内容を変更しない。通常の履歴スナップショットや不明な資料がある場合は作成・移動・削除・上書きをせず停止する。
4. 空の`history/`に限り、サマリーパート、詳細パート、統合判定用8項目を持つ`history/index.md`を作成する。既存の監査用履歴やタスク行を推測で複製しない。既存スナップショットがある場合は作成せず停止する。
5. `result/current-task.md`の初回タスク情報を確認し、台帳へ既知の1行だけを登録する。未確認の値を推測で補完しない。
6. サマリーの短縮状態、詳細の10項目、統合判定用8項目、初回タスク行、`result/current-task.md`との一致、読取可能性、Git追跡対象外を確認する。

## 初期台帳の形式

初期作成時は、サマリーと詳細を分ける。サマリーは人間向け、詳細はAI・運用向けとする。詳細は次の10項目をこの順序で使用し、統合判定用パートは状態と最終更新を除く8項目で構成する。

```markdown
# History Index

このファイルは`<作業ディレクトリroot>/history/index.md`に置き、ローカル管理とし、Git追跡対象外とする。

## サマリーパート

| task-id | 状態 | タスク名 | 目的 | 最終更新 |
| --- | --- | --- | --- | --- |
| `TASK-xxx` | 未着手 |  |  |  |

サマリー・詳細パートのhisi状態は`未着手`、`対応中`、`完了`の3種類に限定する。`継続`、`保留`、`継続評価`、`効果確認待ち`、`未有効化`はhisi状態ではなく、対応理由・停止理由・IMP/IR内部ライフサイクルとして別欄または正本へ記録する。詳細パートでは状態の理由や受入・効果確認などを省略しない。統合判定用パートは状態列を持たず、この制約の対象外とする。

## 詳細パート

| task-id | タスク名 | 目的 | 対象リポジトリ | ローカルパス | ベースブランチ | 機能・レイヤー | タスク概要 | 状態 | 最終更新 |
| --- | --- | --- | --- | --- | --- | --- | --- | --- | --- |
| `TASK-xxx` |  |  |  |  |  |  |  |  |  |

## 統合判定用パート（候補判定の正本）

| task-id | タスク名 | 目的 | 対象リポジトリ | ローカルパス | ベースブランチ | 機能・レイヤー | タスク概要 |
| --- | --- | --- | --- | --- | --- | --- | --- |
| `TASK-xxx` |  |  |  |  |  |  |  |
```

初回タスクのtask-idは、対象プロジェクトで確定した論理タスク台帳の採番規則に従う。`F-xxx`、`IMP-xxx`、ファイル名、日時をtask-idの採番根拠にしない。

## 新規タスク切替時の履歴化ゲート

新規taskを開始する場合は、初期化済みの履歴領域を次の確認にも使用する。明示トリガーであることとOwnerの現行taskの扱いを先に確認し、切替の選択がない状態では履歴操作・task-id採番・新規memo作成を行わない。

### task-id採番時の対応中登録

新しいtask-idを確定した直後に、履歴退避を待たず`history/index.md`のサマリー・詳細・統合判定用パートへ同じtask-idの行を登録する。サマリーと詳細の状態は必ず`対応中`とし、統合判定用パートは状態列を持たない。登録内容は、その時点で確認できる`current-task.md`のtask-id、タスク名、目的、対象リポジトリ、ローカルパス、ベースブランチ、機能・レイヤー、タスク概要だけを使用し、未確認値を推測で補完しない。

- task-id採番、3表への登録、3表のtask-id集合・数値昇順・共通項目の照合を、Planner接続と後続worker接続より先に完了する。
- すでに同じtask-idの3行が存在し、内容と状態が一致する場合は再登録せず、既存行を使用する。行の欠落、不一致、重複、順序比較不能、更新失敗は停止として記録し、Planner・後続worker・完了・履歴操作へ進まない。
- taskが完了した場合は、同じ3行の状態を`完了`へ更新し、退避先とmanifestを追記する。新しい行を追加してはならない。

### 再開taskの追記スナップショット

`history/<task-id>/`に同じ論理task-idの再開前スナップショットが存在し、その資料を入力としてtaskを再開した場合、既存`docs/`、`result/`、manifestは不変のまま保持する。再開後のクローズ断面は`history/<task-id>/continuations/<退避日時>/`へ新しい追記スナップショットとして保存する。

- 追記スナップショットは、再開元、再開理由、退避日時、退避理由、現行taskの状態、対象資料、原典パス、Owner判断、未完了事項を記録した`manifest.md`と、その時点の`docs/`・`result/`で構成する。
- 既存の再開前スナップショット、既存manifest、既存追記スナップショットは変更・削除・上書きしない。退避日時の重複、既存追記先の存在、読取不能、対応関係不明は停止する。
- `history/index.md`は同じtask-idの行を追加せず、既存3行の状態・最終更新だけを更新する。サマリー・詳細・統合判定用パートのtask-id集合、昇順、共通項目を照合する。
- 追記スナップショット、既存再開前スナップショット、hisi既存行、現行`current-task.md`、task-logの対応を照合してから現行`docs/`・`result/`を初期化する。

- 現行`docs/`と`result/`を同じtask-idの履歴領域へ退避し、manifestにtask-id、タスク名、状態、元project/thread、退避元・退避先、日時、理由、対象資料、再開条件を記録する。
- 退避後にmanifest、`history/index.md`の該当行、退避先のdocs/resultを相互照合する。index行はtask-id、目的、対象、状態、未完了事項、Owner判断、履歴パス、正本・根拠の観点で確認し、内容の所属も照合する。既存indexは削除・再作成せず、既存行を保持して新規退避情報を追記・挿入する。
- 照合が成功するまで旧docs/resultの削除・初期化、新規issue-memo、current-task、active taskの作成を行わない。部分成功、欠落、読取不能、内容不一致、hisi更新失敗は停止として記録する。
- 照合成功とOwner承認後は、クローズ・終了・中断または新規task切替のいずれであっても、現行docs/resultを初期化する。新規task切替時だけ新規taskの初期資料を作成し、クローズ・終了・中断時はactive taskなしの初期状態とする。
- 新規task-idは論理タスク台帳、既存履歴、manifest、`history/index.md`との一意性を確認してから確定し、確定直後に本節の対応中登録を完了する。同一projectにactive taskが存在する場合は新規activeを作成せず、現行taskを残すなら別project・別thread等へ案内する。

## 完了条件

### 履歴表のソート順

`history/index.md`のサマリーパート、詳細パート、統合判定用パートは、`task-id`の数値部分を基準に昇順で並べる。新しいtaskを追加する場合も、該当する昇順位置へ挿入する。task-idを比較できない、重複する、または3表のtask-id集合が一致しない場合は履歴更新を完了扱いにせず停止する。並び替えは行順だけを変更対象とし、履歴原本・manifest・状態・Owner判断は変更しない。

次をすべて満たした場合だけ、初期化完了とする。

- `history/`がローカルに存在する
- `history/index.md`がローカルに存在し、読み取れる
- サマリーパート、詳細パート、統合判定用パートが存在する
- 詳細パートの10項目と統合判定用パートの8項目が存在する
- 初回タスクの既知情報が`result/current-task.md`と一致する
- 未確認値を推測で補完していない
- `history/`全体がGit追跡対象外である

## 停止条件

- `history/`に通常の履歴スナップショットまたは不明な資料があるのに`history/index.md`がない（`history/task-legacy-history-backup/`は除く）
- `history/index.md`が読めない、形式が異なる、必須項目が欠落している
- 初回タスクの情報を`result/current-task.md`と一致させられない
- Git追跡対象外であることを確認できない
- 既存履歴の移動、削除、改名、上書きが必要になる

停止時は、期待値、実際値、根拠、影響、停止理由、再開条件を記録し、履歴操作・統合判定・タスク切替を開始しない。
