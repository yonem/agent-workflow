# 履歴領域の初期化ルール

scope: all-workers
scope: all-threads
status: active

## 目的

`history/`をGit追跡対象外のローカル領域として運用する場合でも、新規運用開始時からタスク退避、復旧、統合候補判定が停止しないよう、履歴領域と`history/index.md`を安全に初期化する。

## 初期化の適用タイミング

- agent-workflowを新しい対象リポジトリへ初めて展開した時
- 初回タスクの`result/current-task.md`を作成する前または作成直後
- タスク退避、復旧、統合候補判定を開始する前に、履歴領域の初期化が未確認である時
- 既存の`history/`を持たない移行先で、初回の履歴台帳を準備する時

初期化済みの移行先で`history/index.md`が欠落、読取不能、形式不一致になった場合は、初期化として上書きせず、履歴操作を停止してOwnerへ報告する。

## 初期化手順

次の順序で実施する。特定の言語、shell、実行可能プログラム、外部ライブラリは前提にしない。

1. `history/`の存在、`history/index.md`の存在、Git追跡対象外の設定を確認する。
2. `history/`が存在しない場合だけ、空のローカル履歴領域として作成する。
3. `history/index.md`が存在しない場合、`history/`に通常の履歴スナップショット（`history/<task-id>/`）や不明な資料がないことを確認する。今回の特殊な保全領域である`history/task-legacy-history-backup/`は、この初期化判定の対象外とし、内容を変更しない。通常の履歴スナップショットや不明な資料がある場合は作成・移動・削除・上書きをせず停止する。
4. 空の`history/`に、サマリーパート、詳細パート、統合判定用8項目を持つ`history/index.md`を作成する。既存の監査用履歴やタスク行を推測で複製しない。
5. `result/current-task.md`の初回タスク情報を確認し、台帳へ既知の1行だけを登録する。未確認の値を推測で補完しない。
6. サマリーの短縮状態、詳細の10項目、統合判定用8項目、初回タスク行、`result/current-task.md`との一致、読取可能性、Git追跡対象外を確認する。

## 初期台帳の形式

初期作成時は、サマリーと詳細を分ける。サマリーは人間向け、詳細はAI・運用向けとする。詳細は次の10項目をこの順序で使用し、統合判定用パートは状態と最終更新を除く8項目で構成する。

```markdown
# History Index

このファイルは`<作業ディレクトリroot>/history/index.md`に置き、ローカル管理とし、Git追跡対象外とする。

## サマリーパート

| task-id | 状態 | タスク名 | 目的 | 最終更新 |
| --- | --- | --- | --- | --- |
| `TASK-xxx` | 未着手 |  |  |  |

状態は`完了`、`継続`、`対応中`、`保留`、`未着手`の5種類に限定する。詳細パートでは状態の理由や受入・効果確認などを省略しない。

## 詳細パート

| task-id | タスク名 | 目的 | 対象リポジトリ | ローカルパス | ベースブランチ | 機能・レイヤー | タスク概要 | 状態 | 最終更新 |
| --- | --- | --- | --- | --- | --- | --- | --- | --- | --- |
| `TASK-xxx` |  |  |  |  |  |  |  |  |  |

## 統合判定用パート（候補判定の正本）

| task-id | タスク名 | 目的 | 対象リポジトリ | ローカルパス | ベースブランチ | 機能・レイヤー | タスク概要 |
| --- | --- | --- | --- | --- | --- | --- | --- |
| `TASK-xxx` |  |  |  |  |  |  |  |
```

初回タスクのtask-idは、対象プロジェクトで確定した論理タスク台帳の採番規則に従う。`F-xxx`、`IMP-xxx`、ファイル名、日時をtask-idの採番根拠にしない。

## 新規タスク切替時の履歴化ゲート

新規taskを開始する場合は、初期化済みの履歴領域を次の確認にも使用する。明示トリガーであることとOwnerの現行taskの扱いを先に確認し、切替の選択がない状態では履歴操作・task-id採番・新規memo作成を行わない。

- 現行`docs/`と`result/`を同じtask-idの履歴領域へ退避し、manifestにtask-id、タスク名、状態、元project/thread、退避元・退避先、日時、理由、対象資料、再開条件を記録する。
- 退避後にmanifest、`history/index.md`の該当行、退避先のdocs/resultを相互照合する。index行はtask-id、目的、対象、状態、未完了事項、Owner判断、履歴パス、正本・根拠の観点で確認し、内容の所属も照合する。
- 照合が成功するまで旧docs/resultの削除・初期化、新規issue-memo、current-task、active taskの作成を行わない。部分成功、欠落、読取不能、内容不一致は停止として記録する。
- 新規task-idは論理タスク台帳、既存履歴、manifest、`history/index.md`との一意性を確認してから確定する。同一projectにactive taskが存在する場合は新規activeを作成せず、現行taskを残すなら別project・別thread等へ案内する。

## 完了条件

次をすべて満たした場合だけ、初期化完了とする。

- `history/`がローカルに存在する
- `history/index.md`がローカルに存在し、読み取れる
- サマリーパート、詳細パート、統合判定用パートが存在する
- 詳細パートの10項目と統合判定用パートの8項目が存在する
- 初回タスクの既知情報が`result/current-task.md`と一致する
- 未確認値を推測で補完していない
- `history/`全体がGit追跡対象外である

## 停止条件

- `history/`に通常の履歴スナップショットまたは不明な資料があるのに`history/index.md`がない（`history/task-legacy-history-backup/`は除く）
- `history/index.md`が読めない、形式が異なる、必須項目が欠落している
- 初回タスクの情報を`result/current-task.md`と一致させられない
- Git追跡対象外であることを確認できない
- 既存履歴の移動、削除、改名、上書きが必要になる

停止時は、期待値、実際値、根拠、影響、停止理由、再開条件を記録し、履歴操作・統合判定・タスク切替を開始しない。
