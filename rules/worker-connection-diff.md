# worker接続差分確認ルール

## 目的と責務

本ルールは、Ownerが明示的にヘルスチェックを依頼したとき、前回の完了済みヘルスチェックと今回のworker一覧を読み取り比較し、Ownerが手動判断できる差分記録を作るためのルール・プロンプト・Markdown様式である。特定言語、shell、実行可能プログラム、外部ライブラリは使用しない。

- `rules/worker-health-check.md`: worker一覧の取得順、状態判定、Owner確認、health-checkの原典
- `threads/<thread-name>/docs/health-check.md`: 各回のworker一覧と取得結果の人間向け正本。本ルールは全文を複製しない
- 旧`threads/<thread-name>/result/health-check.md`: 既存タスクの保全資料。明示指定がない限り現行比較元にしない
- `threads/<thread-name>/result/worker-connection-diff.md`: 比較可能な2回目以降だけに作成する専用差分記録
- `threads/<thread-name>/docs/task-progress.md`: 共通進捗・受入観点・Owner判断の正本
- `threads/<thread-name>/result/changes.md`: worker固有の実施結果、停止理由、未確認事項、次worker

本ルールはworker状態を変更せず、他の整合性確認・状態サマリーの出力を必須入力にしない。差分分類とOwner判断への引き渡しだけを行い、workerの作成、削除、アーカイブ、復元、移動、置換、状態変更を自動化しない。

## 起動条件と比較回数

1. Ownerがヘルスチェックまたはworker接続差分確認を明示的に依頼する。
2. `current-task.md`の対象project、スレッド、リポジトリ、実行ディレクトリ、Worker Registryを確認する。
3. 比較元と比較先の取得日時、取得者、取得範囲、ページング、個別確認の成否を別々に記録する。
4. 1回目は比較元がないため、差分を確定しない。Ownerへ「比較元なし・次回以降に比較」と提示し、差分を正常差分として作成しない。
5. 比較可能な2回目以降で、比較元・比較先が同じ対象projectとスレッドに対応し、必要な取得が完了し、取得中の状態変化がない場合だけ`threads/<thread-name>/result/worker-connection-diff.md`を作成する。

## 比較元の選択

原則として、現在の対象project・対象スレッドに対応する直近の完了済み`docs/health-check.md`を比較元にする。現行docsにない場合は、Ownerが指定した履歴のhealth-check資料と対応するmanifestを候補として確認する。旧`result/health-check.md`は保全資料として明示指定された場合だけ参照する。

比較元は次をすべて満たす場合だけ採用する。

- 対象project、対象スレッド、対象リポジトリ、実行ディレクトリが現在のTask Contextと一致する
- 取得日時、Ownerの明示トリガー、現行一覧・アーカイブ一覧・個別thread確認の取得範囲が記録されている
- Worker Registry、役割名、thread、project所属、host、アクセス可否、状態、重複、未確認範囲が区別されている
- 前回記録が完了済みで、取得失敗だけの記録ではない

別project、別スレッド、対象範囲不一致、未完了、取得失敗のみの記録は比較元に確定せず、`比較元未確認`としてOwner判断へ渡す。

## 比較先の取得

`rules/worker-health-check.md`の取得順をそのまま使用し、次の情報を比較先の証跡とする。

1. 現行thread一覧の取得日時、対象project範囲、ページング範囲、取得成否
2. アーカイブthread一覧の取得日時、対象project範囲、ページング範囲、取得成否
3. 比較元に記録された期待threadのproject横断検索結果
4. 役割名ごとの候補、対象project内外、期待threadとの一致
5. 候補ごとのproject、thread、host、アクセス可否、実行中・アーカイブ済み・確認済みの状態
6. 現在のWorker Registry、対象リポジトリ、実行ディレクトリ、branchとの照合

取得中に状態が変わった可能性がある場合、比較先を安定した一時点として扱わず、差分を確定しない。

## 差分分類

比較元と比較先の期待役割範囲を先に正規化する。前回が標準6役割、現在が3役割など、期待範囲の変更はworker消失と別に記録する。

| 分類 | 判定条件 | Owner引き渡し |
| --- | --- | --- |
| 追加 | 比較先で対象project内の新しい役割/threadが確認され、比較元に対応候補がない | 追加理由、project、thread、根拠。自動削除・置換なし |
| 消失 | 比較元で確認済みの候補が、一覧・アーカイブ・個別確認完了後も確認できず、アクセス不能等を除外できる | 消失候補として提示。自動復元・再作成なし |
| project不一致 | 候補はあるが、期待projectまたは対象projectと異なる | 不一致・対象外として提示。対象projectへ算入しない |
| thread不一致 | 役割または候補のthreadが比較元、Registry、比較先で一致しない | 不一致として提示。旧thread削除・置換なし |
| 状態変更 | 同一候補の実行中、確認済み、アーカイブ済み、アクセス不能などが前回から変化 | 状態変更として提示。実行中・不安定を消失としない |
| 重複 | 同一役割に複数候補がある、または候補を一意に対応付けられない | すべての候補を提示。不足数の水増し・自動整理なし |
| 期待一覧変更 | current-taskまたはOwner指定の期待役割範囲が前回と異なる | worker追加・消失ではなく範囲変更として提示 |
| 比較対象外 | 別project、別スレッド、Ownerチャット、初期化用、期待範囲外の候補 | 差分数へ算入せず参考根拠として残す |
| 未確認 | 一覧取得失敗、ページング未完了、個別読取失敗、メタデータ欠落、取得中の状態変化 | 正常・追加・消失を確定せず停止 |

現在一覧にいないことだけでは`消失`にしない。アーカイブ済み、アクセス不能、別project、ページング未完了、取得時点の差が残る場合は、それぞれの分類または`未確認`とする。

## 比較不能・停止条件

次のいずれかに該当する場合は差分を確定せず、比較可能性を`比較不能`または`未確認`としてOwner判断へ渡す。

- 比較元がない、比較元の対象project・スレッド・範囲が一致しない、または前回取得が未完了
- 現行一覧、アーカイブ一覧、個別thread読取のいずれかが失敗、部分成功、ページング未完了、タイムアウト
- project、thread、role、host、アクセス可否、状態を一意に照合できない
- 比較先の取得中にworker状態が変化し、同時点の一覧として確定できない
- 期待一覧の変更とworkerの消失を区別できない
- Owner判断が未回答、保留、不明、対応不明である
- 自動作成、削除、アーカイブ、復元、移動、置換、状態変更が必要になる

停止時は、失敗範囲、影響、未確認事項、再確認条件を`changes.md`へ記録する。`health-check.md`の既存全文を書き換えたり、差分結果で置き換えたりしない。

## 専用差分記録の作成条件と形式

比較可能な2回目以降だけ、`threads/<thread-name>/result/worker-connection-diff.md`を作成する。本文の章立てや表形式は固定せず、比較元・比較先の原典パスと参照箇所、差分分類、判定、停止要否を記録する。`docs/health-check.md`とは別管理とし、health-check本文を複製しない。

- 比較先取得日時:
- 対象project:

## Owner判断プロンプト

差分一覧をOwnerへ提示し、各分類の根拠、未確認範囲、手動対応の要否を確認する。未回答・保留・不明な判断と今回新たに発生した増分判断だけをOwner回答ブロックへ記載し、回答済みの判断は再掲しない。Owner回答ブロックにはOJ行だけを記載する。判断を自動適用せず、残件がある間は次の操作へ進まない。

```text
OJ-xxx（要約: <分類>のworker接続差分を手動整理するか）=yes
```

差分確認情報ブロック：

```text
対象project: <projectId>
対象スレッド: <thread-name>
比較元: <pathと取得日時>
比較先: <pathまたは取得記録と取得日時>
推奨対応: 差分を確認し、状態変更はOwnerが明示した場合だけ手動で実施する
```

残件がない場合は、`Owner判断残件：なし`、`回答プロンプト：なし`を`changes.md`へ記録する。

## Reviewer受入観点

- 比較元・比較先・取得日時・取得範囲・取得失敗が再現可能に記録されている
- 1回目を差分確定せず、比較可能な2回目以降だけ専用resultを作る条件が守られている
- 追加、消失、project不一致、thread不一致、状態変更、重複、期待一覧変更、比較対象外、未確認が別分類になっている
- 比較不能、取得失敗、ページング未完了、アクセス不能、確認中の状態変化で停止している
- Owner判断へ渡すだけで、自動作成・自動アーカイブ・自動修正をしていない
- `health-check.md`全文を複製せず、比較元・比較先と根拠を参照している
- `rules/worker-health-check.md`の取得順・状態判定・Owner確認と矛盾していない
