# 実装媒体ルール

実装媒体は一律に固定しない。Plannerは、対象リポジトリの実態、taskの変更対象、既存媒体、Owner承認済み範囲、許可・禁止操作を計画へ記録してから、媒体を判定する。

- 文書中心リポジトリでは、Markdownのルール、テンプレート、チェックリスト、プロンプト、および結果ファイルを用いる。
- コードを含む開発リポジトリでは、承認済み範囲に限り既存コード、テスト、静的解析、ビルドを扱える。
- 混在リポジトリでは変更対象ごとに媒体と許可操作を分離し、拡張子だけで判定しない。
- 判定不能、承認範囲不明、既存媒体と変更対象の対応不明の場合は、実装・検証を開始しない。

## 禁止

- 承認範囲外の特定のプログラミング言語による実装
- 承認範囲外のshell、PowerShell、バッチ、スクリプト、実行可能プログラムの追加・実行
- 承認範囲外の外部ライブラリ、パッケージ、ランタイム、専用アプリケーションの導入
- コードによる自動削除、アーカイブ、復旧、worker接続、Owner判断の自動適用
- 実装媒体を理由にしたOS別の運用分岐

## 技術依存の例外

共通仕様は、役割、能力、入出力、状態、判定基準、証跡、停止条件で評価できる媒体中立な形を正本とする。特定技術が参照例ではなく実装に必要な場合は、共通仕様へ直接組み込まず、`rules/development-improvement-record.md`の例外記録に、依存理由、適用範囲・期間、代替可否、移行時影響、Owner判断、利用不能時の停止条件、分離先を記録する。記録のない依存は採用せず、移行先の初回サイクルを妨げる未確認の依存は未有効化として停止する。

## 実装方法

- 機能はルール、プロンプト、テンプレート、Markdown台帳、手順、判定基準として表現する
- 実行環境やOSに依存する処理、または新規依存が必要になった場合は、承認済み計画に含まれるかを確認し、含まれなければ停止してOwnerへ報告する
- 検証は文書構造、適用条件、入力例、出力例、停止条件、Owner判断の受け渡しを確認する
- 既存の言語実装やshellプログラムが見つかった場合は、未受入として扱い、Ownerの明示承認に従って整理する
