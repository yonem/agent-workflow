# 共通ルールの冪等性・再実行安全性

## 適用範囲

- `rules/local/`を除く、`rules/`配下のすべての共通ルールファイルに適用する。
- README、worker定義、共通テンプレート、移行先導入資料など、共通運用を定義する資料にも適用する。
- task固有の`threads/<thread-name>/docs/`・`result/`、履歴スナップショット、git追跡外のローカルルールは、実際の証跡として固定値を記録してよい。

## 禁止する表現

共通ルールへ、特定の実体や過去の状態に依存する次の表現を、恒久的な役割・発火条件・完了条件・処理対象として固定してはならない。

- 特定のIR-ID、task-id、OJ-ID、IMP-ID
- 特定のprojectId、thread名、branch、パス、環境名
- 特定のtask・過去実行に依存する日付、時刻、件数、試行回数、状態、固有名
- 「次は必ずこのID」「常にこの件数」「このファイルが必ず存在する」など、現行状態から導出できない断定
- 前回実行の結果、順序、採番、ファイル存在を前提にした処理

例示値を記載する場合は、プレースホルダー、`例：`の明示、または現行値ではないことを明記する。実体値を要求する場合は、論理台帳・現行資料・実測値から毎回取得する。

ただし、必須項目数、固定列名、状態集合、識別子の形式、承認・再試行回数の上限など、実体ではなく共通ポリシーを定義する定数はこの禁止対象ではない。これらは仕様として明示し、特定タスクの実績値・現在の件数・個別IDと混同しない。再実行時には、そのポリシーを現行対象へ適用し、対象の存在や状態を固定値から推測しない。

## 再実行ゲート

- 同じ指示を再実行しても、重複作成、別識別子の再登録、状態の巻き戻り、不要な上書き・削除が発生しないことを定義する。
- 再実行時は対象の存在、正本、識別子集合、状態、変更履歴を確認し、同一状態なら変更せず結果だけを記録する。
- ID、順序、件数、状態、ファイル存在を推測で補完しない。
- 不一致、重複、欠落、比較不能がある場合は、共通ルールの処理を完了扱いにせず、期待値・実際値・根拠・影響・再開条件を記録する。

## ルール変更時の確認

共通ルールの追加・更新・移行時は、変更前後に次を確認する。

```text
[ ] 特定の実体値を恒久条件として固定していない
[ ] 例示値と現行値を区別している
[ ] 再実行時の重複・巻き戻り・不要操作を防止している
[ ] 現行状態・論理台帳・実測値から値を取得する経路がある
[ ] rules/local/以外の参照先へ適用範囲を反映している
```
