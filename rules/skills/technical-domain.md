# 技術領域skill共通定義

- skill-id：`technical-domain`
- 目的：技術領域skillを媒体中立に定義する。
- 適用範囲：技術領域skillの設計・導入前検証。
- 対象外：特定技術の無承認導入、ライセンス不明skill。
- 入力：役割、能力、対象範囲、依存、出典、安全性情報。
- 出力：技術非依存の定義、適用境界、検証結果、採用可否。
- 発動条件：技術領域skillの導入または評価要求。
- 停止条件：依存・ライセンス・危険操作・prompt injection・撤回方法が不明。
- 競合：既存rulesや他skillと責務が重なる場合はOwner判断まで停止。
- 状態：候補／発動中／成功／停止／失敗／中断。
- 検証：役割、入出力、判定基準、証跡、停止条件の媒体中立性を確認。
- 証跡：skill定義、Security Operator result、task-log。
- Owner責任：登録・採用・例外・撤回を承認する。
- 更新・撤回：依存不能、重大な安全性問題、責務重複時に旧版を保全して撤回する。

- 名称：技術領域skill共通定義
- 責務・能力：技術依存を分離し、導入前の安全性・依存・ライセンスを判定する。
- 完了条件：必須項目、導入前検証、停止条件、撤回方法を記録し、Ownerが採用可否を判断できる。
- 優先順位：安全性確認、既存正本、Owner承認を発動より優先する。
- 依存：出典、依存ファイル、権限、更新責任。
- 安全性・ライセンス確認：出典、ライセンス、危険操作、prompt injection、撤回方法を導入前に確認する。
- 次回評価日：導入後の初回運用完了時にOwnerが設定する。
- 適用記録：発動条件、適用範囲、確認結果、採用可否、停止・撤回理由をtask-logへ記録する。

技術領域skillは、特定の言語・フレームワーク・媒体を必須前提にせず、役割、能力、入力、出力、状態、判定基準、証跡、停止条件で定義する。技術名は参照例に限定し、実装依存・例外依存を分離記録する。

## 外部skill事前検証

出典、ライセンス、依存、権限、危険操作、prompt injection、更新責任、撤回方法、利用不能時の停止条件を確認する。確認不能またはライセンス不明のskillは採用しない。移行先の共通rules、worker定義、テンプレート、記録先、責任者、停止条件が揃うまで未有効化とする。
