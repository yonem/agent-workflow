# ローカルルール運用

## 目的と責務境界

共通 `rules/` に採用できない作業リポジトリ固有、利用シーン固有、期間限定、または機密境界付きのルールは、`rules/local/` に分離して管理する。`rules/` は全project共通の安全基準・停止条件・worker手順の正本であり、`rules/local/` は適用条件が限定されたルール本文の正本である。

`README.md`、`AGENTS.md`、worker定義、task資料は参照先と責務を案内する。個別ローカルルールの本文を複製せず、適用中の状態・条件・証跡は対象taskの `docs/task-progress.md` または担当workerの `result/` に記録する。Owner判断は `docs/owner-jadge.md`、対応前後の確認は `docs/operation-check.md` を正本とする。

## 配置・Git管理・命名

- ローカルルールの正本配置は `rules/local/` 直下とする。
- ルール本文は `rules/local/<rule-name>.md` とする。
- `<rule-name>` は目的を表す英小文字・数字・ハイフンの組合せとし、task-id、run-id、専用連番を含めない。
- 同一目的のルールを複数ファイルへ分割しない。適用条件または責務が異なる場合だけ分ける。
- 同名の正本が既にある場合は上書きせず、Owner判断へ停止する。
- `rules/local/` とその配下はGit管理外とする。Git管理外でも存在、正本、適用条件、責任者、状態、証跡の確認を省略しない。

## ローカルルール本文の最小テンプレート

各ローカルルールは、少なくとも次の意味を追跡できる本文を持つ。見出し順は固定しないが、空欄や判定不能を推測で補わない。

```markdown
# <ルール名>

## ルールの状態
- 状態：作成／確認／適用／変更／停止／退役
- 更新時点（Asia/Tokyo）：
- 更新責任者：
- Owner確認：要／不要／確認済み

## 適用条件
- 対象リポジトリ：
- 対象ローカルパス：
- 対象ブランチ：
- 対象機能・レイヤー：
- 対象利用シーン：

## 適用内容
- 適用するルール：
- 共通rulesとの関係：追加制約／具体化／上書き（保護対象外のみ）
- 期待する証跡：

## 停止・退役条件
- 競合・判定不能時：
- 適用停止条件：
- 退役条件：
```

長い根拠、変更履歴、例外一覧、機密情報の詳細は本文へ混在させず、該当する正本・worker result・Owner判断へ分離する。

## 読込・適用タイミング

存在確認と適用判定は次の境界で行う。

1. タスク開始時
2. worker接続前
3. 作業開始前
4. ルール参照・判断が必要になった時
5. Reviewer受入前
6. Documenter記録前
7. 移行先で初期化・復元する時

判定順序は、共通rulesの読込、`rules/local/` の存在・正本・責任者確認、対象リポジトリ・ローカルパス・ブランチ・機能/レイヤー・利用シーンの照合、対象外または判定不能の分類、共通rules保護対象との競合確認、ローカルルール間の重複・競合確認、適用結果と証跡の記録、条件完全一致かつ競合なしの場合の適用とする。適用確認を記録せずに作業を開始しない。

条件が完全一致しないルールは対象外とし、一部しか確認できない場合は判定不能として停止する。完全一致、競合なし、正本・責任者確認済みの場合だけ自動有効化できる。

## 優先順位・保護対象・競合

優先順位は次のとおりとする。

1. 共通rulesの安全性、禁止事項、Owner承認、停止条件、履歴保全、1 active制約、禁止実装媒体などの保護対象
2. 適用範囲に完全一致したローカルルール
3. 保護対象外の共通rulesの既定動作
4. 一般的な推測や会話上の慣行

ローカルルールは保護対象を緩和・無効化できない。保護対象との衝突、ローカルルール同士の競合、優先順位の判定不能、正本・責任者・条件の不明は、ローカルルールを適用せずOwner判断へ停止する。保護対象外の共通rulesは、適用範囲内でローカルルールによる具体化・上書きを許可する。

## 証跡・状態・ライフサイクル

適用時は、正本パス、適用条件と照合結果、状態、更新時点、更新責任者、共通rulesとの競合確認、ローカルルール間の競合確認、Owner判断、停止理由、再開条件を追跡可能にする。状態は `作成 → 確認 → 適用 → 変更・再確認 → 停止または退役` とし、変更時は旧条件と新条件、適用中taskへの影響を確認する。停止時は理由・影響・再開条件、退役時は適用中taskがないことと必要な保全を記録する。

## 移行・復元・欠落

移行先では、共通rules、`rules/local/` の存在、対象リポジトリ、ローカルパス、ブランチ、機能・レイヤー、利用シーン、正本、責任者、停止条件を再確認する。条件完全一致、競合なし、正本・責任者確認済みの場合だけ自動有効化する。

`rules/local/` はGit管理外のため、移行先へ自動では引き継がれない。ローカルルールへの依存がある場合は、Ownerまたは責任者が正本を移行先の `rules/local/` へ明示的に配置してから、存在・正本・責任者・適用条件・競合を確認し有効化する。依存がない場合は移行しないことと欠落を記録し、共通rulesだけで継続する。

`rules/local/` または対象ルールが欠落した場合、推測生成、無断複製、自動復元は行わない。ローカルルールへの依存がないことを確認できる場合は、欠落を記録したうえで共通rulesのみで継続できる。依存がある、適用対象が判定不能、正本・責任者・条件が不明な場合はOwner判断へ停止する。復元はOwner指定の正本・履歴・resultだけを参照し、履歴原本・manifest・スナップショットを変更しない。

## 参照先

- 共通rulesの適用範囲・優先順位：`rules/README.md`
- 対象taskへの案内：`README.md`、`AGENTS.md`
- worker固有の読込・証跡責務：`worker-definitions/`
- 対応前後比較と根拠区分：`rules/operation-check-report.md`
- taskの状態・適用証跡：`threads/<thread-name>/docs/task-progress.md`
- Owner判断：`threads/<thread-name>/docs/owner-jadge.md`
