# PJ定義書：agent-workflow

## 1. 目的

CodexなどのAIエージェントを複数の役割に分担させ、調査・計画・実装・検証・レビュー・記録を一定の手順で繰り返せる、公開利用可能な開発ワークフローのひな型を提供する。

本PJの成果物は、特定の業務システムそのものではなく、新規PJへコピーして利用できる「運用ルール、成果物テンプレート、開始手順」である。

## 2. 利用者と課題

| 利用者 | 困りごと | 提供する価値 |
| --- | --- | --- |
| PJオーナー | AIへの指示や判断点が毎回変わる | ゴール、制約、承認点を定型化 |
| 開発者 | AIの作業状況や引き継ぎ内容が分からない | ファイルによる状態共有 |
| レビュアー | 何を根拠に合格としたか追えない | テスト結果・レビュー結果を保存 |
| 新規参画者 | PJ固有の前提を理解しにくい | 導入順序と参照先を明示 |

## 3. 対象範囲

### 対象

- AIチームの役割分担
- ファイルを介したエージェント間のリレー
- 人間の承認ポイント
- 作業開始からレビュー完了までの標準手順
- Codexへ渡す初回指示のひな型
- 公開リポジトリで安全に運用するためのルール

### 対象外

- AIエージェントの自動起動基盤そのもの
- 本番環境への自動デプロイ
- GitHub、Slack、チケット管理ツールとの自動連携
- 特定のLLMベンダーやモデルへの固定
- 秘密情報を含む実PJデータ

## 4. 完了条件

- 新規PJの担当者が、導入手順に沿って作業を開始できる
- Planner、Implementer、Tester、Reviewer、Documenterの責任範囲が明確である
- 各役割の成果物がファイルとして引き継がれる
- テスト結果とレビュー結果を根拠付きで判定できる
- 人間の承認なしに、マージ・リリース・本番操作へ進まない
- ループ回数、時間、失敗回数のハードストップを設定できる
- 公開しても問題ない内容だけで構成されている

## 5. 判断が必要な事項

| 判断事項 | 初期方針 |
| --- | --- |
| 実行環境 | Codexのローカル作業環境 |
| 状態共有 | リポジトリ内のMarkdownファイル |
| 変更単位 | 1タスク1ブランチ、1コミット1目的 |
| 承認者 | Owner。小規模PJでは開発者が兼務可 |
| 自動化範囲 | 検証と記録まで。マージ・リリースは人間承認 |
| 公開範囲 | 汎用テンプレートのみ。個別PJ情報は持ち込まない |

## 6. リスクと対策

| リスク | 対策 |
| --- | --- |
| AIが目的を誤解する | 要件、対象外、完了条件をファイルで固定 |
| 同じ作業を繰り返す | 最大試行回数と停止条件を定義 |
| 変更が衝突する | ブランチまたはワークツリーを分離 |
| テスト成功だけで品質を誤認する | Reviewerが要件・設計・安全性を独立確認 |
| 秘密情報を公開する | コミット前のスキャンと人間確認 |
