# 要件定義書：agent-workflow v1

## 1. 機能要件

| ID | 要件 | 受入条件 |
| --- | --- | --- |
| FR-001 | PJの目的と対象範囲を記録できる | Project Charterに目的、対象、対象外、完了条件がある |
| FR-002 | タスクを実装可能な単位へ分解できる | Implementation Planに前提、変更対象、手順、検証方法がある |
| FR-003 | エージェントの役割を分担できる | 5役以上の責任と成果物が定義されている |
| FR-004 | 役割間で状態を引き継げる | 次の担当者が前のチャットを読まずに成果物を理解できる |
| FR-005 | 自動検証の結果を記録できる | Test Resultにコマンド、結果、未検証項目がある |
| FR-006 | 独立レビューを記録できる | Review Resultに指摘、重要度、対応、残課題がある |
| FR-007 | 失敗と判断を蓄積できる | Task Logに試行、失敗理由、判断、教訓がある |
| FR-008 | 人間の承認を要求できる | 計画、計画外変更、外部操作、マージ、リリースに承認欄がある |
| FR-009 | ループを停止できる | 試行回数、時間、連続失敗数の上限を設定できる |
| FR-010 | 公開リポジトリで安全に利用できる | 秘密情報をテンプレートに含めず、公開前チェックがある |

## 2. 非機能要件

| ID | 要件 | 受入条件 |
| --- | --- | --- |
| NFR-001 | 可読性 | Markdownとコードブロックで構造を追える |
| NFR-002 | 再現性 | 同じ入力と手順で同じ検証を再実行できる |
| NFR-003 | 監査性 | 誰が何を根拠に判断したかを追跡できる |
| NFR-004 | 拡張性 | 役割、外部コネクタ、検証手段を追加できる |
| NFR-005 | 安全性 | 本番操作と秘密情報の取り扱いを既定で禁止する |
| NFR-006 | 低導入コスト | 特定の有料サービスなしでテンプレートを利用できる |

## 3. 典型的な1タスクの状態

```text
未着手
  ↓
調査中
  ↓
計画作成
  ↓
人間承認
  ↓
実装中
  ↓
自動検証
  ├─ 不合格 → 原因分析 → 修正 → 再検証
  └─ 合格
        ↓
      レビュー
        ├─ 指摘あり → 修正 → 再検証
        └─ 指摘なし
              ↓
          人間承認
              ↓
            完了
```

## 4. 合格判定

合格は「テストが成功した」だけではなく、次の全条件を満たした状態とする。

- 要件と対象範囲に対する変更漏れがない
- 自動テスト、Lint、型チェックなどが成功している
- 未検証項目と既知の制約が記録されている
- レビュー指摘が解消またはOwnerに受け入れられている
- 秘密情報、計画外変更、不要な依存がない
- マージまたはリリースを人間が承認している
