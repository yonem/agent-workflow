# アーキテクチャ

## 1. 全体構成

```text
Owner（人間）
  │ 目的・制約・承認
  ▼
Orchestrator（任意）
  │ タスク割当・停止条件・進捗確認
  ├── Planner       → implementation-plan.md
  ├── Implementer   → ソースコード・テスト
  ├── Tester        → test-result.md
  ├── Reviewer      → review-result.md
  └── Documenter    → task-log.md

共有状態：リポジトリ内Markdownファイル
```

サブエージェントは別チャットであってもよいが、チャット履歴を正式な引き継ぎ情報にしない。引き継ぎの正本はリポジトリ内の成果物とする。

## 2. 成果物の依存関係

```text
current-task.md
  ↓ Planner
implementation-plan.md
  ↓ Owner承認
実装・テスト
  ↓ Tester
test-result.md
  ↓ Reviewer
review-result.md
  ↓ Documenter
task-log.md
```

## 3. 役割と権限

| 役割 | 実施すること | 実施しないこと |
| --- | --- | --- |
| Owner | 目的、優先順位、承認、最終判断 | AIの自動判定だけで本番承認しない |
| Planner | 調査、分解、計画 | 承認前に実装を開始しない |
| Implementer | 承認済み計画を実装 | 計画外の大規模変更を独断で行わない |
| Tester | 検証を実行し結果を記録 | 成功結果を推測で記載しない |
| Reviewer | 要件、設計、安全性を独立確認 | 実装者の自己レビューだけで合格にしない |
| Documenter | 判断、失敗、教訓を記録 | 事実と推測を混同しない |

## 4. ループの運用

このループはAIによる完全自動改善機構ではない。AIが反復作業を担い、人間がゴール、制約、承認、停止判断を担う開発プロセスである。

- 開始時：Ownerが目的、対象、対象外、完了条件を確定する
- 各ループ前：PlannerまたはOrchestratorが次の作業を決める
- ループ中：AIが実装・検証・修正を行う
- ループ終了時：成果物と検証結果を更新する
- 判断時：人間が計画承認、計画外変更、マージ、リリースを判断する
- 停止時：上限到達や不明点を記録し、Ownerへ報告する

## 5. ハードストップ初期値

| 制限 | 初期値 | 到達時の動作 |
| --- | ---: | --- |
| 1タスクの自動試行回数 | 5回 | 停止して原因を報告 |
| 連続検証失敗 | 2回 | 停止して計画を再確認 |
| 1ループの実行時間 | 30分 | 状態を保存して停止 |
| 計画外ファイル変更 | 1件でも | 人間承認まで停止 |
| 本番・外部書き込み | 常に禁止 | Ownerの明示承認が必要 |
